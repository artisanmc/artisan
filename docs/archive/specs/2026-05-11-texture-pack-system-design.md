# Texture Pack System — Design Spec

**Date:** 2026-05-11
**Status:** Approved
**Replaces:** `docs/specs/main-spec.md` § 9 (Resource Pack)

## Goal

Let the user visually enrich their Artisan menus with:

1. **Custom backgrounds** (textures that replace/cover the chest GUI background)
2. **Glyphs/overlays** (decorative icons positioned in pixels in the menu)
3. **Arbitrary text** in the menu, static or dynamic via placeholders, with optional custom fonts

The system must work **with or without** an external pack plugin (Oraxen/Nexo/ItemsAdder), while integrating with these plugins when they are present (reference their glyphs, do not duplicate).

## Architecture

```
┌───────────────────────────────────────────────────────────┐
│  EDITOR (React)                                            │
│  • Assets tab (global library per server_key)              │
│  • WYSIWYG title composer: layers (bg, glyphs, text)       │
│  • Asset picker (Artisan/Oraxen/Nexo/ItemsAdder filter)  │
└──────────────────────┬────────────────────────────────────┘
                       │ POST /api/assets (upload)
                       │ PUT  /api/packs/.../menus (AssetId refs)
                       ▼
┌───────────────────────────────────────────────────────────┐
│  BACKEND (Bun + Postgres)                                  │
│  • assets table: scoped by server_key                      │
│  • resource pack generator: merges all assets → zip        │
│    triggered on asset CRUD                                 │
│  • GET /api/resource-pack/:server_key/:hash.zip            │
│    immutable HTTP cache                                    │
│  • WS broadcast `resource_pack_updated` → plugin           │
└──────────────────────┬────────────────────────────────────┘
                       │ WS resource_pack_updated (hash, url)
                       │ HTTPS GET pack zip
                       ▼
┌───────────────────────────────────────────────────────────┐
│  PLUGIN (Kotlin/Paper)                                     │
│  • On player join: player.setResourcePack(url, hash...)    │
│  • Stack-compatible pack (coexists with Oraxen)            │
│  • On menu render: compiles MenuTitleLayer[] → MiniMessage │
└───────────────────────────────────────────────────────────┘
```

**Key decisions**:

- A single resource pack per `server_key` (all Artisan packs merged into it)
- Asset library global to the `server_key` (not to the pack)
- Cache busting by hash in the URL
- The plugin pushes the pack to the player (`setResourcePack`), coexistence via pack stack 1.20.3+
- External glyphs (Oraxen/Nexo/ItemsAdder) are **referenced** but **never** included in the Artisan pack

## Domain Model

### Asset (global entity)

```ts
type AssetType = "texture" | "glyph" | "font";

interface Asset {
  id: AssetId;              // "asset_a1b2c3", generated by backend
  serverKeyId: ServerKeyId;
  type: AssetType;
  name: string;             // unique per (serverKey, type), e.g. "shop_bg"
  width: number;
  height: number;

  // for type=glyph:
  ascent?: number;          // default: height-1
  codepoint?: number;       // auto-assigned in U+E000–U+F8FF

  // for type=font (MCFonts import):
  fontMeta?: {
    namespace: string;      // e.g. "artisan:my_font"
    glyphMap: Array<{
      char: string;
      texture: string;
      ascent: number;
      height: number;
    }>;
  };

  createdAt: Date;
  updatedAt: Date;
  contentHash: string;      // SHA1 of the PNG/font
}
```

### MenuTitle (replaces the old `title: LText`)

```ts
type MenuTitleLayer =
  | { kind: "background"; assetId: AssetId }
  | { kind: "glyph"; assetId: AssetId; x: number; y: number }
  | { kind: "text"; value: LText; x: number; y: number;
      fontAssetId?: AssetId;  // undefined = vanilla font
      color?: string }
  | { kind: "external_glyph";
      provider: "oraxen" | "nexo" | "itemsadder";
      glyphName: string; x: number; y: number };

interface Menu {
  // ...
  title: MenuTitleLayer[];
  // ...
}
```

### ExternalGlyph (backend cache, read-only)

```ts
type ExternalGlyph = {
  provider: "oraxen" | "nexo" | "itemsadder";
  namespace: string;        // e.g. "oraxen", "nexo"
  glyphName: string;
  char: string;             // codepoint
  textureUrl: string;       // served by backend (PNG decoded from the WS bundle)
  width: number;
  height: number;
  ascent: number;
};
```

### Runtime compilation (plugin)

`MenuTitleLayer[]` → MiniMessage string:

- Artisan background/glyph → `<font:artisan:default><offset:Xpx></offset></font>`
- Vanilla text → `<offset:Xpx><color:...>text</color></offset>`
- Custom font text → `<offset:Xpx><font:artisan:my_font>text</font></offset>`
- External glyph → `<font:oraxen:default></font>`

(where the character after `<offset:Xpx>` or inside `<font:oraxen:default>` is the Unicode codepoint allocated to the glyph in the Private Use Area, e.g. ``. Real values are assigned by the backend generator.)

Layer order determines z-order (first = back, last = front). The `<offset:>` tags let each layer be positioned independently.

## Resource Pack Generation

### Triggers

- Asset CRUD (upload/edit/delete) → synchronous regeneration
- Manual trigger: `POST /api/resource-pack/:server_key/rebuild`
- **No** regeneration on menu publish (the pack only depends on assets)

### Zip structure

```
artisan-pack.zip
├── pack.mcmeta              # format 22 (1.21+)
├── pack.png                 # Artisan icon (fixed MVP)
└── assets/
    └── artisan/
        ├── font/
        │   ├── default.json # aggregates standalone glyphs + refs minecraft:default
        │   └── <name>.json  # 1 per imported font
        └── textures/
            └── font/
                ├── <glyph_id>.png
                └── <font_name>/
                    └── <char>.png
```

Example `font/default.json`:

```json
{
  "providers": [
    { "type": "reference", "id": "minecraft:default" },
    { "type": "bitmap", "file": "artisan:font/coin_icon.png",
      "ascent": 8, "height": 9, "chars": [""] },
    { "type": "bitmap", "file": "artisan:font/shop_bg.png",
      "ascent": -8, "height": 200, "chars": [""] }
  ]
}
```

### Backend pipeline

1. Read all `Asset` WHERE `serverKeyId = X`
2. Allocate codepoints (stable across regenerations, stored on Asset)
3. Generate font JSONs (default.json + per-font files)
4. Stream-build the zip in memory
5. SHA1 of the zip → `{hash}`
6. Write `data/resource-packs/{serverKeyId}/{hash}.zip`
7. Update `ServerKey.resourcePackHash` + `resourcePackUrl`
8. GC: keep the last 3 hashes (download grace period)
9. WS notify plugin: `{ kind: "resource_pack_updated", url, hash }`

### Codepoint allocation

- Range: `U+E000` to `U+F7FF` (Private Use Area; we avoid `U+F800–U+F8FF`, often used by Oraxen/Nexo)
- Sequence per `serverKeyId`, first free, stable (never reused while the asset exists)
- If > 6144 assets: refuse upload, message "asset library full"

### HTTP endpoints

```
GET /api/resource-pack/:server_key_id/:hash.zip
  → 200 + zip stream, Cache-Control: immutable, ETag: hash
  → 404 if hash unknown

GET /api/textures/asset/:asset_id
  → raw PNG preview (for the editor)

GET /api/external-glyphs/:server_key_id/:provider/:glyph_name.png
  → external glyph preview (decoded from the WS bundle)
```

## Plugin Distribution

### Sending to the player

```kotlin
fun pushPackToPlayer(player: Player) {
  val info = currentPackInfo ?: return
  player.setResourcePack(
    info.uuid,             // UUID.nameUUIDFromBytes(hash.toByteArray())
    info.url,
    info.sha1Bytes,        // 20 bytes
    info.prompt,           // MiniMessage Component
    false                  // required = false
  )
}
```

**When to push**:
- `PlayerJoinEvent` + 20 ticks delay
- On receiving WS `resource_pack_updated` → re-push to all online players

**UUID stable per hash**: `UUID.nameUUIDFromBytes(hash.toByteArray())` → repeated sends are idempotent in the client's pack stack.

### Additional WS messages

| Message | Direction | Content |
|---|---|---|
| `hello_ack` | backend → plugin | + `resource_pack: { url, hash } \| null` |
| `resource_pack_updated` | backend → plugin | `{ url, hash }` |
| `external_glyphs_changed` | plugin → backend | `{ hash }` |
| `external_glyphs_request` | backend → plugin | `{}` |
| `external_glyphs_bundle` | plugin → backend | `{ hash, data: base64(gzip(json)) }` |

### Plugin configuration

```yaml
# plugins/Artisan/config.yml
resource-pack:
  enabled: true
  prompt: "<gold>Pack Artisan</gold>"
  send-on-join: true
  send-delay-ticks: 20
```

### Player refusal

- `PlayerResourcePackStatusEvent` → log DECLINED / FAILED_DOWNLOAD
- No kick (pack `required = false`)
- Menus show `□` instead of glyphs if the pack is refused

## External Glyphs Integration

### Runtime detection (plugin)

```kotlin
interface GlyphSource {
  val provider: String
  fun isAvailable(): Boolean
  fun listGlyphs(): List<ExternalGlyph>
  fun registerReloadHook(callback: () -> Unit)
}

class OraxenGlyphSource : GlyphSource { ... }
class NexoGlyphSource : GlyphSource { ... }
class ItemsAdderGlyphSource : GlyphSource { ... }
```

Same pattern as `CustomItemsManager`.

### Bundle sent to the backend

The plugin reads the source PNGs (`plugins/Oraxen/pack/...`, etc.), builds a JSON:

```ts
[
  {
    provider: "oraxen",
    namespace: "oraxen",
    glyphName: "iron_coin",
    char: "",
    ascent: 8,
    height: 9,
    width: 8,
    pngBase64: "..."
  },
  ...
]
```

Gzip+base64, sent via `external_glyphs_bundle`. The backend decodes, serves via `/api/external-glyphs/...`.

### Hot reload

The Oraxen/Nexo/ItemsAdder reload events are hooked (already in place for custom items) → re-bundle → WS notify.

### Runtime compilation

```kotlin
val glyph = externalGlyphs.lookup(layer.provider, layer.glyphName)
  ?: return PLACEHOLDER  // □ if glyph absent
"<font:${glyph.namespace}:default>${glyph.char}</font>"
```

### No inclusion in the Artisan pack

External glyphs are delivered to the player by the Oraxen/Nexo/ItemsAdder pack itself (stack 1.20.3+). Artisan only **references** the namespace at runtime.

## Export / Import

### `.zip` format

```
my-pack.zip
├── manifest.json             # format version, metadata
├── pack.json                 # the Pack (AssetId refs)
└── assets/                   # optional
    ├── manifest.json         # list of bundled assets (name, type, contentHash, originalId)
    ├── <asset_name>.png
    └── fonts/
        └── <font_name>/
            ├── font.json
            └── glyphs/
                └── <char>.png
```

### Export

UI dialog:
- ☑ Include used assets (N assets, ~XKB)
- ☐ Include external glyph references metadata (warning: the recipient must have Oraxen)

Backend: `GET /api/packs/:pack_id/export?include_assets=true` → zip stream, walks `AssetId` refs, dedups.

### Import

UI dialog:
- Drop/browse `.zip`
- Preview: "N menus, M assets bundled"
- Conflict resolution per asset:

| Case | Action |
|---|---|
| Name does not exist | Create + remap refs |
| Name exists, same contentHash | Reuse + remap refs |
| Name exists, different contentHash | Ask (reuse / rename / skip) |

### AssetId remap algorithm

```ts
const idMap = new Map<AssetId, AssetId>();

for (const bundled of importedManifest.assets) {
  const resolved = resolveConflict(bundled);
  idMap.set(bundled.originalId, resolved.id);
}

remapAssetIds(pack, idMap);  // walk: menu.title[*].assetId, appearances[*].assetId
```

### External glyph refs

Kept intact on import. If the external plugin is absent on the recipient's side, glyphs show `□` at runtime + persistent UI warning.

### Backwards compat

Old exports (without assets, without `MenuTitleLayer[]`) → `formatVersion = 0` → in-place migration (legacy `LText` title → single text layer).

## Migration

`Menu.title: LText` → `Menu.title: MenuTitleLayer[]`:

```ts
function migrateTitle(legacy: LText | MenuTitleLayer[]): MenuTitleLayer[] {
  if (Array.isArray(legacy)) return legacy;
  return [{
    kind: "text",
    value: legacy,
    x: 8,
    y: 5,
    fontAssetId: undefined,
    color: undefined,
  }];
}
```

Applied:
- Backend: on DB read (JSONB, no SQL migration)
- Plugin: on YAML parsing (parser tolerates both formats)
- Editor: on pack ingestion (Zustand init)

## Sub-project Decomposition

The MVP scope covers the 3 axes (bg + glyphs + custom text), split into **6 independent sub-projects**, each with its own implementation plan:

| # | Sub-project | Deliverables | Depends on |
|---|---|---|---|
| **1** | **Asset library + backend** | DB schema, CRUD endpoints, PNG upload, codepoint allocation, asset detail panel UI | — |
| **2** | **Resource pack generator** | Zip generation pipeline, HTTP endpoint, plugin distribution (`setResourcePack`) | 1 |
| **3** | **MenuTitleLayer + WYSIWYG composer** | Domain migration, title composer UI, runtime compiler (plugin) — text + Artisan glyphs | 1, 2 |
| **4** | **Background + custom fonts** | Bg layer kind, import MCFonts dialog, font asset type, font rendering preview | 3 |
| **5** | **External glyphs (Oraxen/Nexo/ItemsAdder)** | `GlyphSource` adapters, WS messaging, external glyphs picker | 3 |
| **6** | **Export/import `.zip` with assets** | Export dialog, zip pipeline, import conflict resolution, AssetId remap | 1, 3 |

**Delivery order**: 1 → 2 → 3 → (4, 5, 6 in parallel).

Each sub-project produces an end-to-end usable state.

## Open Questions / Future Work

Out of MVP, to be taken up in future specs:

- **`required: true` admin option**: kick if the pack is refused
- **Custom `pack.png`**: upload of a custom icon by the admin
- **Glyph studio**: integrated pixel-art editor (create a glyph without uploading)
- **Animated glyphs** (Minecraft 1.20+ supports animation frames in font bitmaps)
- **Reverse bridge**: "export an Artisan asset to the Oraxen config"
- **Asset marketplace**: public sharing of assets between servers

## Decision Log

| Decision | Choice | Rationale |
|---|---|---|
| Own pack system vs integrate | **Hybrid** | Independence + optional integration with existing plugins |
| Pack delivery | **Plugin `setResourcePack()`** | Pack stack 1.20.3+ allows coexistence without admin config |
| Asset scope | **Server-wide library** | Consistent with server_keys; portability via export bundle |
| Asset workflow | **Upload + library + MCFonts import** | Covers simple and advanced |
| Title UX | **Visual WYSIWYG** | More accessible than raw MiniMessage |
| External glyphs | **Pure reference, no inclusion** | Avoids duplication; respects Oraxen/Nexo ownership |
| MVP scope | **3 full axes** | Functional consistency, split into 6 manageable sub-projects |
| Export format | **Standard `.zip`** | Universally recognized, no OS friction |
