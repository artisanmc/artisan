# Data Sources Redesign — Plan C1: Domain refactor

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Refactor the domain types to introduce `FieldType`, `DataSource`, `ConnectorSpec`, `SourceRef`, transform `ContextInput` into a discriminated union (primitive | sourceRef), add `Pack.dataSources` and `Pack.importedConnectors`, and drop `Menu.sampleContext`. Get the codebase compiling and tests green on the new shape. UI for the new fields comes in Plans C2 and C3 — this plan only modifies what's needed to compile and pass existing tests.

**Architecture:** Pure type/state refactor. New types are additive (won't break anything). Existing `ContextInput` is the only breaking change — old `type: "list"`/`type: "object"` shapes vanish (no `kind: "primitive"` admits them); consumers narrow on the union. `Menu.sampleContext` is removed from types and from any consumer that read it (MenuGroup preview, MenuProperties SampleContextEditor, uiStore.sampleContextFormat). Per the spec, **no data migration** — existing localStorage packs may break, accepted pre-launch.

**Tech Stack:** TypeScript 5.7, immer (existing reducers), zustand state, vitest. No new dependencies.

**Spec reference:** `docs/superpowers/specs/2026-05-03-data-sources-redesign-design.md` §1 (Domain model), §4 (Migration). C2 (Data sources page) and C3 (Connector import) are separate plans.

**Out of scope (C2/C3):**
- Page Data Sources UI
- Schema editor / value editor for DataSources
- ContextInput picker UI for "primitive vs sourceRef" choice (C1 ships minimal MenuProperties refactor — just enough to not crash)
- Connector YAML parser / file import workflow

After the existing exports (somewhere in the file — placement doesn't affect anything), add the FieldType, DataSource, and ConnectorSpec definitions:

```typescript
/**
 * Recursive type descriptor for a data source's shape. Discriminated by
 * `kind`. Primitives (string/number/integer/boolean) are leaves.
 * `list` and `object` recurse — `list of {kind: object, fields: [...]}` is
 * the canonical "list of records" shape used by most connectors.
 */
export type FieldType =
  | { kind: "string" }
  | { kind: "number" }
  | { kind: "integer" }
  | { kind: "boolean" }
  | { kind: "list"; of: FieldType }
  | { kind: "object"; fields: { name: string; type: FieldType }[] };

/**
 * Admin-made source of typed data. Lives on the pack and is referenced
 * by menus via `ContextInput { kind: "sourceRef", ref: "pack:<id>" }`.
 * Renaming the source updates referencing inputs atomically (cf.
 * accountStore reducers in Plan C2).
 */
export interface DataSource {
  id: DataSourceId;
  name: string;
  type: FieldType;
  /**
   * Concrete data, validated against `type` at edit time. Stored as
   * unknown because the shape varies — runtime/preview consumers cast
   * after schema lookup.
   */
  value: unknown;
}

/**
 * Spec of a plugin-sourced connector. Either pushed to the editor via
 * WS at server connection (plan paid) or manually imported from a YAML
 * file generated by the Interfaze plugin (plan free). Stored on the
 * pack so exports ship with their connector specs.
 */
export interface ConnectorSpec {
  /** Stable namespaced ref, e.g. "chestshop:items", "essentials:warps". */
  ref: string;
  type: FieldType;
  /** 3-5 sample items validated against `type`. */
  sample: unknown;
}
```

Add a `coerceDefault` helper near the top of MenuGroup.tsx (or extract to a shared util if it makes sense):

```typescript
function coerceDefault(
  value: string | undefined,
  type: "player" | "string" | "integer" | "number" | "boolean",
): unknown {
  if (value === undefined || value === "") {
    // sensible per-type fallback for preview
    switch (type) {
      case "player":
      case "string":
        return "";
      case "integer":
      case "number":
        return 0;
      case "boolean":
        return false;
    }
  }
  switch (type) {
    case "integer":
    case "number": {
      const n = Number(value);
      return Number.isFinite(n) ? n : 0;
    }
    case "boolean":
      return value === "true";
    case "player":
    case "string":
    default:
      return value;
  }
}
```

Same fix for `ItemTooltip.tsx` if it reads `menu.sampleContext` similarly.
