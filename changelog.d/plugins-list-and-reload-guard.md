- **Added**: a server's page in the editor lists its **Plugins**: Artisan and every plugin built on it, directly or not, with its version, its jar file, whether it runs and what it depends on. A first step toward updating modules from the editor. Protocol 1.5 adds `suite_plugins` to a server's announcement (`GET /api/v1/servers/:server/plugins`) and the `plugin` that holds each of `installed_modules`; an older leaf lists none, and the section asks to update it.
- **Added**: a plugin reload is no longer silent. Paper cannot unload a plugin: a reloader (PlugMan...) swaps the jar, and the plugins that use its classes keep the old ones. When Artisan is enabled while plugins that depend on it already run, or disabled while the server keeps running, it logs at SEVERE the plugins left broken and asks for a restart. When a plugin of the suite is disabled while the server runs and others still use it (ArtisanGuildQuests uses MSQuests and ArtisanGuilds), Artisan names them and the order to reload them in. Dependencies are read from `plugin.yml` and `paper-plugin.yml`, soft ones included, and followed through (MSQuests, then what uses MSQuests).
