- **Added**: Bedrock players see styled menus (Geyser). The editor builds a Bedrock resource pack next to the Java one (`editor/src/lib/pack/bedrock/`): for each chest menu of 3 or 6 rows with its player inventory visible, the composed background (vanilla chest top unless `vanilla_texture: false`, then the `background` and `glyph` title layers), the images of its image buttons (one per state) and `text`/`plain`/`textarea` layers placed as labels, through JSON UI modifications of Geyser's chest screen keyed on a marker in the container title. The hub stores it (`PUT /api/v1/servers/:id/bedrock-pack`, served under `/bedrock-pack/<sha1>.mcpack`) and tells the server (`bedrock_pack_updated`, `bedrock_pack` in `hello_ack`; protocol `1.5`, an older leaf gets it at its next `hello_ack`). The server keeps it in `cache/bedrock-pack/` (`BedrockPackManager`); with `Geyser-Spigot` installed (new soft dependency), every Bedrock player receives it at connection and gets, for a styled menu, the title the pack reads instead of the composed one (`BedrockTitle`, the mirror of `bedrockTitle.ts`). Artisan writes `Geyser-Spigot/custom_mappings/artisan.json` once (the click item under an image button, drawn transparent): one restart the first time. Known limits: only the left click reaches a menu from Bedrock, text layers use the Bedrock default font without MiniMessage formatting (the color tag a value opens with becomes the label's color) and ignore `line_height`; title fields are cut in UTF-8 bytes and found whatever formatting codes the proxy chain puts before the title (Geyser's `§r` and more, up to 30 bytes), player heads show the default skin, `player_inventory: hidden`, other chest sizes, hoppers, droppers, external glyphs and custom fonts stay as Geyser translates them. With Geyser on a proxy, Bedrock players are still recognised (Floodgate here, else the UUID it gives them) but the pack (`cache/bedrock-pack/`) and the mapping (`cache/geyser/custom_mappings/artisan.json`) have to be copied into that Geyser's folders by hand.
